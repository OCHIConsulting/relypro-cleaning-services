## Architecture decision

The public site is generated by Eleventy. The production site remains unchanged, while the approved branch is now also built as a Cloudflare Pages preview so its Function endpoint can be tested without changing DNS or production traffic.

The browser posts first-party JSON to the endpoint configured by the `relypro-lead-endpoint` meta tag. The endpoint validates and normalises input, rejects the honeypot and implausibly fast submissions, applies a ten-minute rate limit using a salted hash of the source IP in KV, calculates a stable idempotency key, checks a 24-hour KV record when bound, generates a public enquiry reference, and only returns success after the configured destination accepts the record.

The storage boundary remains provider-neutral: it can forward the documented JSON over HTTPS, or use the included server-only HubSpot adapter selected by `LEAD_DESTINATION_PROVIDER=hubspot`. The adapter upserts email contacts; for phone/WhatsApp it searches by phone, updates an existing match or creates a contact, then creates an associated deal. The service key never enters browser code.

## Current journey and failure points

Before this change, quote/contact forms only opened WhatsApp. Closing the tab, popup blocking, or not pressing Send meant the enquiry was lost, while the page displayed a handoff message rather than a saved-lead confirmation.

The new journey is: form entry -> client validation -> first-party POST -> server validation -> destination acceptance -> public reference -> optional WhatsApp handoff. On any integration failure there is no false success: fields remain in the DOM, a session-only draft supports reload recovery, and phone/email/WhatsApp fallbacks are shown. A retry reuses the same browser submission ID, enabling deduplication.

## Lead API contract

`POST /api/leads`, JSON only. Required quote fields are: `kind`, `name`, `contact_method`, `contact_details`, canonical `service`, UK `postcode`, `property_summary`, `privacy_acknowledged`, `started_at`, `client_submission_id`, and `landing_page`. `preferred_date` and the three non-personal attribution fields (`utm_source`, `utm_medium`, `utm_campaign`) are optional. The hidden `website` field must remain empty.

Responses:

- `200 { ok: true, reference, duplicate? }` only after persistence or a confirmed duplicate.
- `422 { error: "validation_failed", fields }` for field errors.
- `429 { error: "rate_limited" }` after more than five requests per IP in a ten-minute KV-backed window.
- `503 { error: "unavailable" | "upstream_failure" }` when storage is unconfigured or fails.

The rate-limit key is a salted SHA-256 digest; no raw IP address is written to KV, and each counter expires after ten minutes. KV rate limiting and deduplication are best-effort because KV is eventually consistent; for strict exactly-once creation, the destination must also enforce uniqueness on `client_submission_id` or the calculated idempotency value.

## Analytics data contract

Permitted events: `quote_start`, `quote_submit_attempt`, `lead_capture_success`, `lead_capture_failure`, `whatsapp_handoff`, `phone_click`, and `email_click`. Supporting UI events may include `form_start`, `service_selected`, and `quote_click`.

Permitted parameters are page path, form name, canonical service, non-personal UTM source/medium/campaign, consent state, and a small error class. Never send a reference, name, contact detail, postcode, property summary, message, link text, full `mailto:`/WhatsApp URL, `gclid`, or form value. Analytics loads and events reach GA4 only after valid consent; the local diagnostic event remains available for tests without personal data.

## Rollback

Revert the Phase 1 commit or restore `assets/js/main.js`, `get-quote.html`, `contact.html`, `privacy.html`, and `cookies.html`; remove `functions/`, `lib/lead-core.js`, Phase 1 tests/docs, and the example vars file. No production data migration is needed until a destination has been activated. If rolling back after activation, disable the endpoint secret/binding first and export or retain lead records according to the privacy notice rather than deleting them blindly.
